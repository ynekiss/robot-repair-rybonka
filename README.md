Щоденник розробника — Юніт 2: Оточення і фізика
 Що зроблено:
- Створено повноцінний рівень з тайлсета (Pixels Per Unit = 64, нарізка 3×3) із бордюром на 2 клітинки за межами камери.
- Налаштовано сортування за віссю Y: у Graphics/Renderer2D встановлено Custom Axis (0, 1, 0), Pivot декорацій переведено в Bottom, а у робота — Custom (0.5, 0) зі Sprite Sort Point = Pivot.
- Робот налаштований як префаб із Rigidbody 2D (Gravity Scale = 0, Freeze Rotation Z) та Box Collider 2D у нижній частині спрайта (в області ніг).
- Переписано скрипт руху робота: збір вводу здійснюється в `Update()`, а переміщення — через `rigidbody2d.MovePosition()` у `FixedUpdate()`.
- Створено сітку колізій за допомогою `Tilemap Collider 2D` (Composite Operation = Merge) та `Composite Collider 2D` зі Static Rigidbody 2D. Для тайлів підлоги встановлено `Collider Type = None`.

 Де застрягли та як вирішили:
- Робот спочатку застрягав або дрижав біля перешкод — проблему вирішено переходом з `transform.Translate` на `MovePosition` у `FixedUpdate`.
- Сортування за Y не працювало коректно для високих об'єктів — виправлено виставивши `Sprite Sort Point = Pivot` в інспекторі Sprite Renderer робота та налаштувавши Pivot у Bottom для спрайтів.
 Що зрозуміли про FixedUpdate та колайдери:
- `Update()` залежить від FPS пристрою і підходить лише для зчитування натискань клавіш (`Input.GetAxisRaw`).
- `FixedUpdate()` виконується з однаковим часовим інтервалом і призначений виключно для роботи з об'єктами `Rigidbody2D`.
- Колайдер робота має покривати лише його «ноги» (основу), а не весь спрайт, щоб персонаж міг природно заходити за деталі оточення.
Відхилення від «фізичного паспорта»:
- У фізичному паспорті об'єкти мають реальну гравітацію та тертя. Оскільки наша гра є топ-даун (вигляд зверху), `Gravity Scale` вимкнено (встановлено в 0), а обертання Z зафіксовано (`Freeze Rotation Z`), щоб робот не падав і не перевертався при зіткненні зі стінами.
